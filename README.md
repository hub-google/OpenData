# 企業成長／擴張雷達

這不是「看到公司有異動就說有商機」的查詢站，而是把政府公開資料轉成 **企業未來支出訊號**。

## 核心原則

商機分數看的是：

> 這個事件發生後，公司未來 0–12 個月還有多少合理的新增支出可能？

因此「搬遷完成、改名、一般不明異動」不再自動拿高分；它們只能當佐證。

## 已自動化的資料與訊號

### 主訊號
- **新設立**：公司剛成立，開辦與供應商關係可能尚未固定。
- **增資**：不是「缺錢」，而是資金已到位，後續可能擴產、擴編、設備與專案投入。
- **營業項目新增**：透過經濟部公司營業項目 API 建立逐公司快照，有前次狀態才能判定新增。
- **新設分公司**：利用分公司 API 的 BR_ESTAB_DATE 抓新據點。
- **巨額政府採購履約**：公共工程委員會近一週巨額採購、且仍在履約中的廠商。
- **新工廠登記**：經濟部產業發展署登記工廠名錄；因更新較慢，只在官方登記日期明確時升級。
- **稅籍產業異動**：財政部每日稅籍快照的行業欄位差分。

### 佐證訊號
- **台灣就業通徵才命中**：官方介面單次最多 1000 筆，因此只加分，不以「沒命中」推論沒有徵才。
- **地址變更**：大多屬落後訊號，只搭配其他成長事件時作為擴張佐證。
- **名稱變更／其他公司登記異動**：觀察，不作高優先商機。
- **減資**：偏風險／授信監控，不作一般銷售主名單。

## 每日流程

GitHub Actions 每天台北時間約 08:20：

1. 下載財政部全國營業中稅籍資料。
2. 查經濟部當日公司設立與公司異動。
3. 建立/恢復全國 SQLite baseline。
4. 做資本額、地址、產業、名稱快照差分。
5. 對今日候選公司並行查營業項目與分公司。
6. 比對營業項目歷史快照，偵測真正新增項目。
7. 以分公司設立日偵測新據點。
8. 讀取台灣就業通作徵才佐證。
9. 讀取公共工程委員會巨額採購履約資料。
10. 讀取經濟部登記工廠名錄。
11. 合成事件、Lead Score、商機解釋與建議切入方向。
12. 輸出網站 JSON 與最近 60 天歷史。
13. 發布 GitHub Pages。

## 評分方向

大方向由強到弱：

1. 巨額標案履約／新工廠
2. 新設分公司
3. 增資
4. 營業項目新增
5. 新設公司
6. 稅籍產業異動
7. 搬遷／改名／不明異動

多個訊號同時出現會加分，例如：
- 增資 + 新工廠
- 增資 + 營業項目新增
- 增資 + 新設分公司
- 新設分公司 + 營業項目新增
- 巨額標案 + 增資

## 已知限制

- 營業項目 API 沒有逐項變更日期，因此必須從系統開始累積快照後，才能精準知道「新增了什麼」。第一次看到某家既有公司的項目，只建立 baseline，不誤判。
- 台灣就業通官方介面單次最多 1000 筆，不是全市場完整徵才資料。
- 工廠名錄更新非每日，不把「今天資料集才出現」直接當成「今天才設廠」。
- 全國政府電子採購網目前沒有一個完整、穩定的所有決標公告官方 API；目前先接官方「巨額採購履約」資料。
- 動產擔保公示查詢是公開資料，但目前是互動查詢網站，沒有適合每日批次全量抓取的穩定官方 API；不能假裝已完整接入。
