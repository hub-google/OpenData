## 0. 測試目的、範圍與執行規則

**目的**：站在「真的要靠政府標案賺錢」的使用者角度，驗證能否從「找得到案子」走到「知道值不值得接、能不能接、怎麼備標、怎麼協作與追蹤」，而不是只確認某個按鈕能點。包含匿名訪客、首次投標者、個人接案者、業務開發、標案專員、主管、會計、公司管理者、客服、跨裝置會員與 API 使用者。

**測試前提**：
1. 只在測試用帳號、經授權的真實公開資料及自建假公司資料上操作；絕不代替使用者投標、付費、寄送陌生人訊息或更動正式案內容。
2. 公告來源為第三方彙整的政府採購公開資料；**每項決定均要回到官方公告核對**。資料未公開≠金額為 0；截止日未知≠仍開放；無法決標≠重新招標；同公告列出其他公司≠已證明同場競爭；歷史決標比≠報價指引。
3. 用同一機關、同一正式案號多版本公告，以及「不同案號但相似案名」各準備至少 1 組；沒有符合的真實樣本時，標記資料前置不足，不自行捏造政府案件。
4. 使用三種互相獨立的身分：訪客 A、正式會員 B、正式會員 C；團隊管理員與成員另以經授權身分操作。不得測試、讀取其他實際客戶資料。
5. 測試裝置：桌面 Chrome、Edge、iPhone 尺寸 Safari、Android 360–412px；採真實瀏覽器實作時記錄版本、螢幕寬度、時間、網路及登入狀態。
6. 正常情境驗收必須同時檢查：UI 成功訊息、重新整理後資料仍存在、對應資料表／API 結果符合、沒有跨帳號外洩；需外送的功能還要有**實際供應商送達回執**。
7. **現有狀態提醒**：截至既有 11/10 驗收追蹤，模型金鑰、LINE／Email 外送、正式金流、官方拒絕往來資料 5988 完整同步、真人多角色 E2E 均有未驗收或外部阻礙。以下有這些按鈕的情境依然列入，但不預設它已可用。
8. 目前網站強調免註冊使用，但部分模組原始碼仍寫有正式登入限制（如服務建議書、備標工時、競品追蹤、報表、API Key）。**若訪客被擋住，不要用「需求如此」帶過：要與最新免註冊產品決策核對並提缺陷／規格衝突。**
9. 本文件只新增 Markdown，不改程式、資料庫、金鑰、排程或其他開發中的功能。

**執行結果欄位**（每案例完成後附上）：實測日期與裝置｜實測身分｜案例編號｜使用的公開正式案號（可遮蔽敏感私人資訊）｜操作錄影或截圖檔名｜Network/API 證據｜DB/來源證據｜預期 vs 實際｜PASS/FAIL/BLOCKED/NOT_RUN｜問題編號與嚴重度。**目前全數 NOT_RUN**。

**優先度**：P0＝錯案、錯金額、錯截止、資料外洩或無法完成基本找案；P1＝關鍵工作流中斷；P2＝體驗、匯出、次要分析。狀態只允許 NOT_RUN／PASS／FAIL／BLOCKED／N/A。

| 角色 | 真實使用目的 | 主要入口 |

| A 新手／訪客 | 第一次找可接的政府標案，沒有公司也先比較 | 搜尋、指南、客服、基本追蹤 |
| B 個人接案者 | 想找設計、維護、網站、顧問等低額案件，先看預算與資格 | 快速篩選、案件詳情、商機雷達 |

| D 標案專員 | 管理截標、標書、資格、提出投標與否的決策 | 案件投標準備、文件、待辦、日曆 |
| E 主管 | 同時評估幾個案，決定資源分配 | 決策評估、工時成本、投標成果、報表 |
| F 財務／會計 | 追押標金、履保、驗收與請款 | 合約台帳、提醒、CSV |

| I 資料分析／開發者 | 讀本人收藏與任務，串內部 BI | API Key、REST、MCP |

**準備資料**：①真實且官方來源可查之公開案件甲；②有更正／多公告版本之案件乙；③有官方決標金額與預算之案件丙；④缺預算或官方截止日之案件丁；⑤不同案號但相似名稱之案件戊；⑥自建測試公司「示範資訊服務商」（虛構，不對外刊登）；⑦自建 TXT、DOCX、PDF 有文字層、掃描 PDF、XLSX、圖片各一份；⑧一份舊新版條款內容不同的自製標單；⑨虛構履歷／證照證明不得冒稱真實資格；⑩三個身分及二組團隊。若公開案找不到，填 BLOCKED 並記下查詢條件。

## 2. 八條可交付的端到端使用者故事

### E2E-01｜個人設計師第一次找案：從 0 到「可接／不接」
- **前置**：不登入、沒有收藏；產品為平面設計與活動視覺。
- **流程**：1. 開首頁搜尋「視覺設計」。2. 切「確認截止未到」及「百萬以下」。3. 設預算上限，排除非本業。4. 開兩筆案件逐一查最新公告、公告更正、履約地及官方截止時間。5. 若預算缺值，進官方來源，不以 0 或空字串當可報價基礎。6. 加入適合案到追蹤；設內部決策日、記錄資格疑問。7. 重整並驗證保存。8. 若訪客追蹤被登入牆阻擋，登記規格落差。
- **驗收**：能清楚分辨「可考慮接」、「截止待查」、「無法估價」；結果一案一列、收藏狀態不重複，官方連結可核對；沒有憑案名推定資格。
- **反例**：找不到 100 萬以下案件，應清楚顯示 0 筆或資料缺口，不能推薦任意無預算案件。

### E2E-02｜資訊公司業務：從機關歷史找到可能重購需求
- **前置**：公司服務網路維運；掌握某機關代碼。
- **流程**：1. 在機關情報輸入真實代碼。2. 看年度採購件數、已入庫月別紀錄。3. 看同機關相似名稱但不同案號的候選案件。4. 點候選回詳細公告比對年度、契約期限（僅原文有揭露才看）。5. 查相同機關公開決標廠商。6. 切到商機雷達保存網路維護關鍵字與排除詞。7. 把符合的近期案件加入工作台並記錄拜訪或提問動作。
- **驗收**：只標「可能重購」，不憑歷史推測下一次招標日期；月數與金額只代表已入庫樣本，不把零命中當機關沒採購。

### E2E-03｜標案專員：自動整理資格到投標前最後查核
- **前置**：收藏一個可追溯正式案件，準備合法取得的標書、公司證照。
- **流程**：1. 開案件→投標準備→資格與標書。2. 上傳有文字層 PDF，整理資格、日期、押標金、評選條款。3. 針對掃描頁面執行本機 OCR，逐批核對。4. 儲存私人文件與來源頁碼。5. 在公司資料建測試證照及實績。6. 使用「與公司證照／實績比對」，對缺失標記人工補件。7. 在決策評估填六項證據、選投標／不投標。8. 建立待辦並設定內部截止。9. 匯出清單與日曆。
- **驗收**：每項結論可回溯文件及頁碼；OCR 錯誤標可疑；非公開資訊絕不顯示成官方已確認；上傳行為清楚區分本機處理與雲端保存。

### E2E-04｜主管：比較兩案的利潤與備標成本
- **前置**：已收藏兩案、已登入可儲存私人工時的身分。
- **流程**：1. 查看兩案決標行情的有效比較樣本。2. 打開每案「投標準備→成本與工時」。3. 登記業務、工程師、文件製作的日期與工時，另記現金支出及可選時薪。4. 修改一筆、刪除誤輸一筆。5. 回工作台看成本彙總及人工決策。6. 匯出本人追蹤 CSV。7. 決定集中資源做哪一案並備註理由。
- **驗收**：已支付支出與推算工資分開；不提供臆測毛利率或得標率；沒有時薪者不得被算為 0 成本。

### E2E-05｜財務：得標後履保、驗收、請款追蹤
- **前置**：本人已收藏並自行標記進度的案件。
- **流程**：1. 到合約與保證金管理，分別建立押標金返還、履保返還、驗收、請款事項。2. 記入實際合約來源、手動金額與到期日。3. 檢查前 7／3／1 日站內提醒。4. 人工確認到期、修改或結案。5. 匯出台帳，與公司財務紀錄交叉核對。
- **驗收**：私人金額不冒充官方預算／決標金額；提醒按指定期限去重，不重複建立同一事件；不能代繳或直接對外請款。

### E2E-06｜三人投標團隊：邀請、分工、成員退出
- **前置**：獨立管理員、標案專員、會計各一身分。
- **流程**：1. 建立團隊工作區。2. 產生一次性邀請碼；第二人加入。3. 分享一筆真實案件；分派資格證明與價格試算兩項任務。4. 成員完成並由主管刷新確認。5. 第三個未受邀帳號嘗試開啟團隊資源。6. 邀請碼重複使用、過期後再使用。7. 成員離隊／撤權後再測存取。
- **驗收**：成員操作與工作區一致，非成員不得讀寫；邀請失效不重新開門；不得拿個人私人文件當全員共享。

### E2E-07｜競爭情報：指定廠商→自動報表→提醒
- **前置**：可用本人持久身分，已有一個合法公開之廠商查詢條件。
- **流程**：1. 到監控與提醒→競品追蹤建立名稱／統編。2. 開「查看此廠商的公告」。3. 看真實公告的已明示角色、別名與同公告其他公司。4. 建立每週「市場採購分析」或「標案清單」報表。5. 立即產生一次，預覽與下載 CSV。6. 設關鍵字監控，查看站內通知。7. 若 Email/LINE 尚未配置，檢查是否清楚顯示未啟用而非假送達。
- **驗收**：追蹤、查詢、報表、通知狀態相互連得上；不能把同公告其他公司說成真正競標對手。

### E2E-08｜使用者遇到錯誤：從公開案件缺值到客服結案
- **前置**：找出一筆原文缺預算或官方連結不完整的正式案。
- **流程**：1. 點開案件，看「未知／待核對」標記及官方來源。2. 若有補抓功能，提交一次補抓請求，檢查受理狀態。3. 右下客服→問題回報，選「標案資料錯誤」，填機關、案號、來源及重現步驟。4. 到「我的紀錄」查看工單編號。5. 客服授權管理者在後台回覆（另行獲授權）。6. 使用者重新開網站、補充問題並查看結案狀態。7. 再核對原案與官方來源是否已更正。
- **驗收**：前端不偷偷補假預算、不宣稱已修復；客服只見授權工單，不洩露第三方私人資料。

## 3. 逐功能情境清單（全部 NOT_RUN）

各案例格式：**前置**＝角色與起點；**步驟**＝使用者實際點擊或輸入；**預期**＝驗收結果；**異常**＝必須另外檢查的負向／邊界路徑。執行時請在案例旁補上前述證據，不能以源碼存在代替操作成功。


### 01｜入口、導覽、身分與資料留存

#### UAT-001｜新訪客直接使用（P0）

- **前置**：無登入的乾淨瀏覽器
- **操作步驟**：開首頁→搜尋一般標案→查看詳情→收藏→重新整理。
- **預期結果**：基本搜尋、詳情與產品允許的訪客工作流可使用；不強迫先註冊。
- **負向／邊界**：若收藏／任務模組實際跳登入牆，記下模組和最新免註冊規格衝突。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-002｜六大主選單（P1）

- **前置**：桌面或手機
- **操作步驟**：逐一展開「找標案、我的商機、市場情報、投標管理、文件與資格、提醒與設定」並切回原頁。
- **預期結果**：只移動視圖而非重新建立資料；當前選單醒目且可返回。
- **負向／邊界**：快切 10 次後不得跳錯頁或遺失表單草稿。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-003｜手機與返回定位（P1）

- **前置**：360px、390px、412px
- **操作步驟**：開漢堡選單→進階搜尋→搜尋→開詳情→關閉→返回前一結果。
- **預期結果**：無橫向溢出、按鈕可點、內容不遮擋；保留搜尋條件與頁碼。
- **負向／邊界**：橫豎切換、縮放及長公司名稱都不致覆蓋動作。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-004｜瀏覽器重整與離線（P1）

- **前置**：已建立私人追蹤及未送出的文字
- **操作步驟**：重新整理、開另一分頁、模擬暫時斷網後恢復。
- **預期結果**：已保存資料不丟失；未保存的內容不可假稱已存；網路失敗有明示。
- **負向／邊界**：不可因重試建立重複收藏或重複任務。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-005｜正式帳號登入與同步（P1）

- **前置**：已授權 Email／Google 測試帳號
- **操作步驟**：登入／跨裝置同步→Email 連結或 Google→在裝置一收藏→裝置二登入→立即同步。
- **預期結果**：能綁定本人身分並在另一裝置取得同一人的資料；登出後不能讀私有資料。
- **負向／邊界**：登入取消、失敗、過期連結及重新整理都有合理錯誤。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-006｜變更信箱與刪除帳號（P1）

- **前置**：專用可刪除測試帳號，非正式客戶
- **操作步驟**：申請換 Email→驗證身分→建立備份→輸入現在信箱和「刪除我的帳戶」→確認。
- **預期結果**：錯誤確認不得刪除；成功時只刪本人私有資料，不能波及團隊其他成員。
- **負向／邊界**：擁有未轉移團隊時應阻擋或引導轉移，不得留下孤兒權限。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補

#### UAT-007｜Demo 入口隔離（P2）

- **前置**：一般網址與 ?demo=1 各開一窗
- **操作步驟**：檢查一般站是否隱藏測試捷徑；以 ?demo=1 使用測試帳號並到客服。
- **預期結果**：公開版不誤導使用者為測試環境；Demo 不讀正式客服資料。
- **負向／邊界**：Demo 工單與真會員工單不得互相列出。
- **實測狀態**：NOT_RUN｜**證據**：待補｜**缺陷編號**：待補


### 02｜一般搜尋、快速篩選與資訊正確性

#### UAT-008｜關鍵字搜尋（P0）

- **前置**：現有跨日正式案件
- **操作步驟**：輸入「資安」→搜尋→翻頁→打開第 2 頁最後一案。

## 5. 測試證據範例與問題回報模板

**單一案例記錄**：

- 案例：UAT-___；結果：NOT_RUN / PASS / FAIL / BLOCKED / N/A；執行人：___；時間（Asia/Taipei）：___
- 角色／裝置／瀏覽器：___；測試案號與官方來源：___；測試帳號代號（不寫個資／密碼）：___
- 操作重現：1. ___ 2. ___ 3. ___；預期：___；實際：___
- 證據：截圖 ___；Network HAR（已去識別）___；API 回應碼 ___；允許查核之資料庫紀錄 ___
- 問題：嚴重度 P0/P1/P2；可重現頻率 ___；影響範圍 ___；處理建議 ___

**上線結論規則**：只要有 P0 FAIL、來源／金額／截止誤導、跨帳號洩漏或實際付款未授權，均不得標「可正式上線」。外部服務未配置的情境可列 BLOCKED，但不得用模擬結果取代真實回執。只有截圖還不夠的項目（跨帳號／付款／外送），必須同時提供後端權限或服務商回執。
