## 目前架構

- GitHub Pages：前端定位、附近搜尋、距離排序。
- **不再每 5 分鐘抓全台停車資料，也不讀舊快取。**
- 使用者按「定位並查附近」或「更新車位」時，才依目前座標與搜尋半徑判斷需要查哪些已接縣市。
- 當下直接呼叫地方政府官方停車 API；單一 HTTP / JSON 請求失敗會自動重試最多 3 次，每次都有 10 秒 timeout。
- 縣市交界可同時呼叫多個政府來源，再依座標距離合併排序。
- 若官方 API 連續 3 次失敗，該來源本次直接標示失敗，不拿舊資料冒充即時資料。
- 價格與車位欄位優先採官方直接欄位，不用模糊名稱或自然語言推論補值。

## 已接前端來源

目前 GitHub Pages 已接入所有「已找到確切 endpoint 且能取得座標」的免費來源。使用者查詢時才依定位即時呼叫，不預先每 5 分鐘抓全台。

### 可取得 numeric 即時剩餘格
- 臺北市
- 新北市
- 桃園市
- 臺南市
- 新竹市
- 高雄市
- 彰化縣
- 宜蘭縣
- 臺東縣
- 澎湖縣

### 已接場站／動態頁面，但來源本身未提供 numeric 剩餘格
- 臺中市
- 雲林縣
- 南投縣
- 花蓮縣
- 嘉義市
- 屏東縣（恆春資料）

這些來源仍會出現在地圖與附近清單，但以灰色「無即時數字」呈現，不把燈號、文字狀態或猜測值轉成剩餘格。

目前尚未接進地圖的縣市，是因為尚未找到可公開呼叫且可定位的地方 endpoint，或來源只有地址沒有經緯度。這些不會用模糊比對、猜座標或假資料補齊。

如果官方端點在瀏覽器端因 CORS / TLS / 來源限制失敗，頁面會將該來源標成失敗並保留其他成功來源，不會拿假資料或舊快取補。
