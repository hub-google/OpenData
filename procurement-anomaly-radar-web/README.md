# 政府採購異常雷達

> 目標：用政府公開採購資料找出「值得優先人工查核」的異常模式，而不是自動判定弊案。

## MVP 偵測器

1. **廠商集中**：同機關、同類採購長期由少數廠商取得。
2. **疑似拆單**：短期內出現高度相似、金額接近門檻的多筆採購。
3. **限制性招標集中**：限制性招標比例偏高，且反覆指向同一廠商。
4. **標比異常**：決標金額長期貼近預算／底價，分布異常集中。
5. **價格異常**：規格、數量、服務條件標準化後，單價偏離同類案件。
6. **廠商關聯**：不同投標廠商的公開公司登記資訊出現地址、人員等高度重疊訊號。
7. **拒絕往來紀錄**：交叉比對政府採購拒絕往來廠商公告。
8. **組合異常**：同一案件同時觸發 3 種以上訊號，優先進入人工查核。

## 判讀原則

- **異常不等於違法。**
- 系統使用「查核優先度」，不使用「弊案機率」。
- 每一個訊號都應可回溯到原始公告、欄位與計算方式。
- 正式版必須把採購發生當時的法規門檻與制度背景納入判斷。
- 價格比較必須先標準化規格、數量、保固、維護、施工及其他附帶條件。

## 正式版資料層

預計整合：

- 政府電子採購網招標／決標公告
- 採購預算、底價、決標金額、投標家數、採購方式、決標方式
- 機關與採購類別歷史紀錄
- 公司登記公開資料
- 拒絕往來廠商公開資料
- 同類標案歷史價格資料

## 介面

`index.html` 為可直接部署到 GitHub Pages 的前端 MVP。目前使用模擬案件，以避免在尚未完成證據鏈與人工查核前，對真實機關或廠商做不當指控。


## 證據鏈與來源網址

正式版每一筆歷史採購紀錄都必須保存：
- 標案案號
- 招標公告官方網址
- 決標公告官方網址
- 若機關另有公告頁，保存機關公告網址
- 任何公司登記、拒絕往來或其他交叉資料的原始來源網址

前端規則：**沒有可直接查證的來源 URL，就不得把該筆紀錄當成異常判讀證據。**

目前 MVP 使用模擬案件，因此不製造假的政府公告網址；介面會明確顯示「示意資料｜無真實公告可查證」。
